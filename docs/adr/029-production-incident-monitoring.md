# ADR 029: Production Incident Monitoring & Alert Aggregation

## Status
PROPOSED -> IN-REVIEW

## Constitution Alignment
1. **Rule 19 (Everything Observable):** The system must continuously monitor the Event Bus for critical failures, security alerts, and capacity breaches.
2. **Rule 22 (Production First):** Incidents must be classified by severity (e.g., CRITICAL for double-spend attempts, WARNING for rate limits) to enable rapid response.

## Context
Phase 15.5 requires us to establish a Production Monitoring routine. Since we are processing real financial data and real users, we cannot rely on manual log reading. We need an automated incident reviewer that listens to the system's heartbeat and flags anomalies.

## Decision
We will implement the **ProductionIncidentMonitor** featuring:
1. **Event Bus Listener:** Continuously listens to `SECURITY_ALERT`, `AUDIT_LOG`, and `BETA_CAPACITY_REACHED` events generated by other core engines.
2. **Incident Classification:** Automatically tags events with severity levels (CRITICAL, HIGH, WARNING).
3. **Daily Incident Report:** Aggregates all anomalies into a structured JSON report for the Operations Console to display.
